# Addendum 2026-10-28: what no longer needs an accountant to show us
- Didox ЭСФ Excel template: 60 columns, lines in AO–BH (45 name, 46 ИКПУ, 47 barcode, 48 pharma series, 49 unit *code*, 52 qty, 53 price, 56 amount, 57–58 VAT rate/sum, 59 total, 60 privilege code); header: 2 invoice type id, 3 one-sided type id, 4–7 invoice/contract no. and date as text, 13–26 seller (INN in 14), 27–40 buyer (INN in 28). Source: the text file beside this README.
- Didox unit list: public `GET https://api.didox.uz/v1/measures/all` → 109 entries `{measureId, name}` (1 штук, 5 килограмм, 20 куб. метр, 38 упаковка …). The per-IKPU "package codes" shown on receipts are the Tax Committee's, not Didox's.
- Didox download archive: a zip of zips, per document a JSON (lower-case keys: facturadoc, productlist.products[] with name, catalogcode, catalogname, packagename, count, summa, vatrate, vatsum, deliverysumwithvat …), its PDF, .p7s signatures and a readme; amounts arrive as noisy floats and strings. Source: github.com/odiljonjamoliddinov39-cloud/1C_integration docs/didox.md (third party, read 2026-10-28; not copied here).
- Bank statements in the field: header words Дата, № док, Корреспондент, ИНН, Дебет, Кредит, Сумма, Назначение (Uzbek variants too); totals/balance rows without a date; INN of zeros = unknown payer; acquiring rows (SmartVista) and bank fees without a counterparty; client-bank text exports with `~` separators in Windows-1251 and no headings; several accounts per period (settlement, blocked, transit, currency; currency = account digits 6–8: 000 UZS, 840 USD, 978 EUR, 643 RUB); 1C targets ПоступлениеНаРасчетныйСчет / СписаниеСРасчетногоСчета. Source: the same repo, docs/bank-statements.md (third party).
- 1C UZ 3.0 nomenclature: the IKPU code lives in the attribute titled «Код из классификатора» (ЭДО group), units in «Единица измерения», packaging in «Код упаковки»; our packages/domain/src/onec/sheets.ts NOMENCLATURE_HEADERS already match these names.
