Legend: **[OFFICIAL]** = vendor/state page or a live response from the vendor's own server (probed today with curl);

## 1. DIDOX API

### Verified (official)
- **No public developer documentation exists.** `didox.uz` is an SPA with no API/docs links; `docs.didox.uz` does not resolve; searches for a Didox developer portal return only Контур.Диадок (Russia, unrelated). The official instruction channel `https://t.me/s/didox_instruction` has Excel templates (ЭСФ, Гибридная ЭСФ, ТТН, Произвольный документ, «Шаблон для загрузки ИКПУ.xlsx»), E-IMZO installers and ЭСФ types (стандартная, исправленная, дополнительная, односторонняя, с лотом, с ID договора, с доверенностью, гибридная, СМР, скидка) but **no API or 1C material**.
- **API hosts are real** (curl today, all answer JSON `{"error":"The route \/ could not be found."}` on `/`): `https://api.didox.uz/` (prod), `https://testapi2.didox.uz/` (test; adds `trace_id`), `https://api-partners.didox.uz/` (partner gateway used by the npm SDK).
- **`GET https://api.didox.uz/v1/measures/all`** works **without any auth** (HTTP 200 today). Shape: `[{"measureId":"1","name":"штук"},{"measureId":"5","name":"килограмм"},{"measureId":"38","name":"упаковка"},{"measureId":"2","name":"пачка"},{"measureId":"20","name":"куб. метр"},{"measureId":"36","name":"кВтч"},{"measureId":"7","name":"тонна"},{"measureId":"11","name":"метр"},…]`. Note `measureId` is a **string**; these are Didox's own ids, not tasnif unit ids.
- Didox is "free for most companies"; onboarding is by signing the public offer with an ЭЦП key at registration (gazeta.uz 2019-12-30, norma.uz) [OFFICIAL press, old].

### Third-party / unofficial
**A. GitHub `odiljonjamoliddinov39-cloud/1C_integration`** (default branch `claude/exciting-carson-vcb2hr`, TypeScript/Electron, pushed 2026-10-23). Sources read: PRs #12, #37, #38, #40, #43, #44; `docs/didox.md`; `apps/desktop/src/main/didox/{client,fetch,document}.ts`. The author states the protocol was taken from **Didox's own 1C library «Библиотека электронных документов для Узбекистана» 3.0.15.1 (`uzbled_*`, common module `uzbled_Операторы_Didox`)** handed over by Didox on 2026-10-19, plus an older Postman collection "DIDOX-1C-INTEGRATION" (dev server `devapi.goodsign.biz`, now dropped). Treat as second-hand evidence of the official protocol; the repo itself says several shapes are "not verified against real Didox".
- Servers: prod `api.didox.uz`, test `testapi2.didox.uz` (library constant `uzbled_ЭтоТест`); `didox.uz` is the site, answers 405 to API calls.
- Auth with E-IMZO key: `GET /v1/auth/authId/{serialNumber}` → `{authId}`; sign JSON `{"authId"}` as PKCS#7 with E-IMZO; time-stamp it via `POST /v1/dsvs/timestamp` body `{"pkcs7","signatureHex"}` → `{"success","timeStampTokenB64","isAttachedPkcs7"}` (older `/v1/dsvs/gettimestamp`: prod answered 405); `POST /v1/auth/{taxId}/token` body `{"serialNumber","signature"}` → `{"token","related_companies"}` (24 h; fallback `POST /v1/auth/login` `{"serialNumber","pkcs7"}`); for a person's key `POST /v1/auth/company/{companyTin}/login`. Token travels on every later call as **both headers `api-key` and `user-key`**; the library has **no partner key**. Password login (not built): `POST waltz/goodsign/0.0.1/user/{inn}/token` `{"password"}`.
- Documents: `GET /v1/documents?owner=0|1&page=&limit=(default 20, lib uses 100)&doctype=&status=&dateFrom=&dateTo=&partner=` — **`dateFrom/dateTo` filter by update date, not document date** (repo sends only `dateFrom`, applies `dateTo` on the document's own date); `GET /v1/documents/statistics/all`; `GET /v1/documents/{id}` (data); `GET /v1/documents/{id}/file/true` → `{file:{data:<base64 PDF print form>}}`; `/html/{locale}`, `/pdf/{locale}`, `/file/false`; `POST /v1/documents/{docType}/create` (draft), `POST …/{id}/update/{docType}`, `…/{id}/delete/draft`; `GET|POST /v1/documents/{id}/tosign` `{"action":"accept|reject|cancel","comment"}` → `{data}`; `POST …/sign` `{"signature"}`, `…/reject` `{"signature","comment"}`, `…/delete` `{"signature"}`. **`GET /v1/documents/{id}/downloadrequest` (zip link) is dead on prod** (500 "route … could not be found").
- Profile/catalogs: `/v1/profile`, `/v1/profile/{tin}`, `/v1/profile/update`, `/v1/profile/branches?tin=`, `/v1/profile/taxGap/{tin}`, `/v1/profile/vatRegStatus/{tin}`, `/v1/profile/productClasses`, `/v1/profile/operators`, `/v1/banks/all`, `/v1/measures/all`, `/v1/regions/all`, `/v1/districts/all`.
- `doctype` per the Postman collection: `000` free-form, `001` invoice, `002` invoice ("without an act" per that note — conflicts with B below, where 002 = standard ЭСФ), `005` act, `006` power of attorney, `061` POA Didox-only, `021` invoice return, `008/081` pharma, `052` reconciliation act (used by the repo). Repo creates invoices with `POST /v1/documents/002/create` and letters with `/000/create`.
- `status`: 0 created, 1 signed by self, 2 signed by partner, 3 signed, 4 rejected, 5 deleted, 6 waits for agent, 8 signed by agent, 40 not valid, 60 partner waits for agent (Postman note; conflicts with B).
- **Invoice JSON shape** (lower-case keys, from `document.ts`, parsed on 79 real documents): kind detection `facturadoc`+`productlist` = invoice, `actdoc`+`productlist` = act, `contractdoc`+`owner`+`parts` = contract, `verificationactdoc` = reconciliation, `document`+`documentid` = free-form. Header: `facturaid|actid|contractid|documentid`, `facturatype`, `oldfacturadoc`, `hasrent`/`facturarentdoc`, `sellertin`, `buyertin`, `seller.name|sellername`, `buyer.name|buyername`, `contractdoc.contractno`, `contractdoc.contractdate`. Lines `productlist.products[]`: `ordno`, `name`, `catalogcode` (17-digit MXIK), `catalogname`, `packagename` (unit shown), `count`, `summa` (price), `deliverysum`/`totalsumwithoutvat`, `vatrate`, `vatsum`, `deliverysumwithvat`/`totalsum`, `withoutvat`. Values arrive as numbers, strings and noisy floats (`892.8600000000000136`); TIN is 9 or 14 digits; VAT rates seen 0/12/15. Outgoing create body uses upper-case keys (`FacturaDoc`, `ContractDoc`, `SellerTin`, `BuyerTin`, `ProductList.Products[]` with `Name`, `MeasureId`, `Count`, `Summa`, `TotalSum`, `VatRate`, `VatSum`, `TotalSumWithVat`). Package code / measure id fields on **incoming** lines were not listed by the parser — [UNKNOWN].
- **User zip export**: "a zip of zips: for each document a JSON, its PDF picture, `.p7s` signatures and a readme" (docs/didox.md §"Importing Didox archives"). File naming inside — [UNKNOWN].
- 1C side (same repo): matches 1C nomenclature by the attribute titled «Код из классификатора» (under ЭДО on the Номенклатура form); uses `Справочник.ДоговорыКонтрагентов` by number+date; writes `Документ.СчетФактураПолученный` unposted via a COM-called extension (see §2 iii).

**B. npm `didox` 1.0.6** (author mirzaevoff, modified 2026-01-27, repo `github.com/mirzaevoff/didox`, built from `dist/index.d.ts`): environments `production: https://api-partners.didox.uz/`, `development: https://stage.goodsign.biz/`; headers `Authorization: Bearer <partnerToken>` **and** `user-key: <user token>` (a partner-token model, unlike A); auth `POST /v1/auth/{taxId}/password/{locale}` (ИНН + password) and `POST /v1/auth/company/{companyTaxId}/login/{locale}`; `ListDocumentsParams {owner:0|1, page, limit, status?: number|number[], doctype?, partner?, dateFromCreated?, dateToCreated?, dateFromUpdated?, dateToUpdated?}`; `GET /v1/documents/{id}`, `/v1/documents/{id}/privileges`, `POST /v1/documents/{docType}/create`; profile: `/v1/profile`, `/v1/profile/operators`, `/v1/profile/productClasses`, `/v1/profile/productClassCodes`, `/v1/profile/{taxId}/productClasses/check/{code}/{lang}`, `/v1/profile/branches?tin=`, `/v1/profile/warehouses/{tin}`, `/v1/profile/vatRegStatus/{tin}`, `/v1/profile/taxpayerType/{tin}/{lang}`, `/v1/utils/info/{taxId}`, `/v1/account`. `enum DocumentType`: `002` ЭСФ, `008` pharma ЭСФ, `023` гибридная ЭСФ, `041` ТТН, `005` акт, `006` доверенность, `007` договор НК, `000` произвольный, `052` акт сверки, `054` акт приёма-передачи, `010` многосторонний произвольный, `075` протокол учредителей. `enum DocumentStatus {DRAFT=0, SENT=1, SIGNED=2, REJECTED=3}` (conflicts with A's list). Product line fields in its builders: `catalogCode`, `catalogName`, `name`, `measureId`, `count`, `price`, `vatRate`, `deliverySum`; seller `account` (20 digits), `bankId` (5-digit МФО).

**C.** GitHub issue iRatG/mktplace#63 mentions a Didox "партнёрский токен, документация API и тестовый контур" obtained by request [3P].

## 3. TASNIF.SOLIQ.UZ catalogue access

### Verified (official — live responses from `https://tasnif.soliq.uz/api/cls-api` today, no auth)
- **Bulk Excel**: `GET /excel/get/category?lang=uz|ru|uz_cyrl` → xlsx (HTTP 206/200, `application/octet-stream`; ~439k codes per repo gate-0 report). Columns (0-based, from `scripts/ingest-catalog.ts`): 0 group, 1 class, 2 position, 3 subPosition, 4 brand, 5 attribute, 6 code, 7 name, 8 barcode, 9 strictUnit, 10 strictUnitAlt, 11 packages, 12 recUnitGroup, 13 recUnit, 14 privilege. The export **omits the marking flag and status**.
- **Search**: `GET /elasticsearch/search?search=<q>&size=&page=&lang=uz|ru` → `{success,code,reason,data:[…],recordTotal}`; item fields: `mxikCode, name, description, internationalCode (GTIN), label ("0"/"1" = marking), fullName, group/class/position/subPosition/brand codes+names, attributeName, usePackage ("1"), categoryUnitId, categoryUnitName, unitsName, surveyCategoryId, nonChangeable ("1"), lgotaId, lgotaName, recommendedCategoryUnitName, recommendedUnitsName, packageName, useCard, property, categoryCode, categoryName, mnnName`. Any `lang` value is accepted; multi-word RU queries can return 0 (gate-0).
- **Filter**: `GET /mxik/search/by-params?mxikCode=|gtin=|…&size=&page=&lang=` → Spring page `{data:{content:[CatalogItem], totalElements, totalPages, last, …}}`; CatalogItem has `label` (number), `internationalCode`, `unitCode/unitName`, `commonUnitCode/Name`, `packages`, `units`, `myProduct`. "Not found" = `success:false, code:-1, reason:"not data found"`.
- **Card**: `GET /mxik/get/by-mxik?mxikCode=&lang=` → `{mxikCode, groupName/Code, className/Code, positionName/Code, subPositionName/Code, brandName/Code, mxikName, attributeName, unitCode, unitName, commonUnitCode, commonUnitName, internationalCode, label, useCard, lgotaId, lgotaName, units, myProduct, shortName, mnnName, packages:[…]}`. **Packaging structure** (`packages[]`): `code` (package id, e.g. 1806952), `parentCode`, `mxikCode`, `containerCode` (47), `containerName` («мешок»), `containerNamePl/Pl2`, `unitId` (1), `unitName` («шт.»), `parentValue` (50.0), `name` («50 килограмм»), `type` ("1"), `childNames` («килограмм&&»), `childValues` («1&&»), `isUnitPackage` ("2"), `categoryID/Name`, `checkUser`, `createdAt`, `createdBy`, `children[]`, `childrenValue[]`. A brand-less code (e.g. `00101001001000000`) has one package `{code:1378325, name:"шт.", unitId:1, parentValue:1.0}`.
- **History / status**: `GET /integration-mxik/get/history/{code}` → `{data:{id, pkey, parentPkey, mxikCode, groupNameUz/Ru/Lat, classNameUz/Ru/Lat, positionName…, subPositionName…, brandName, attributeNameUz/Ru/Lat, description, isActive:"1", createdAt, updatedBy, updatedAt, status:0, packageNames:[{code, mxikCode, nameUz («қоп=1 килограмм»), nameRu («мешок=1 килограмм»), packageType:"1"}]}}`. This is the only endpoint exposing **`isActive` and `status`**.
- **Units**: `GET /integration-mxik/references/get/units/all?pageSize=200` → `{data:[{id:111,name:"карат"},{id:88,name:"дона (пэт бутылка)"},…], recordTotal:90}` (90 units; `pageNo`, `lang` accepted).
- **Tax privileges**: `GET /integration-mxik/references/lgota` → `[{id, nameRu, nameUz, nameLatn, docDate (epoch ms), docNum, docNameUz/Ru/Latn, oldId}]`.
- **Groups**: `GET /group?lang=&size=&page=` → `{data:[{code:"001", name, nameUz, nameRu, nameEng, description, mxikCount, logoSvg}]}`.
- Not public: `/package` and `/statistics` → 401; `/integration-mxik/references/get/package/all`, `/mxik/package/by-mxik`, `…/container/all` → 404. `api-tasnif.soliq.uz` (named in a blog) does not resolve.
- **Regulation** (ПКМ №263 of 28.04.2025 «Положение о национальном каталоге», summarised by buxgalter.uz; official act not fetched): code = группа·класс·позиция·субпозиция·бренд·атрибут, brand-less goods end in `000000`; changes to a code or its units take effect **30 days** after deletion/change (announcement on tasnif.soliq.uz and the Tax Committee Telegram), except new codes, name edits and unit attachment; "строго определённые" vs "рекомендуемые" units (one attached unit = strict; first of several = recommended); packaging: only внешняя/транспортная for GTIN goods, потребительская for retail goods without GTIN; ЭСФ accepts only the taxpayer's own created packages and strictly defined units; new codes requested via личный кабинет (ЭЦП), operator creates or refuses; privileges attached by the Tax Committee; from 01.01.2023 goods under mandatory marking get identifying codes, others базовые (gov.uz/soliq). Restricted generalised construction codes: `https://tasnif.soliq.uz/news/5063` (perechen.xlsx, already loaded by `scripts/load-restricted.ts`).

## 4. Performance reference (brief)
- No published benchmark of Excel→1C statement tools at ~1000 rows was found (searches on infostart/habr/42clouds). A Habr case (habr.com/ru/articles/920308) notes that statement-load slowness in 1C came from constant reads and founder queries inside the loader, not parsing — i.e. the 1C write side dominates, not Excel parsing.
- Only third-party datapoints (1C_integration PRs): 26 bank payments entered via its COM extension in one card (model time 15 s for posting); one issued Didox invoice entered as a sale took 9m40 with 18 LLM steps (AI 9m21, 1C 15 s) before they moved lookups into code. Takeaway: budget the 1C-side writes (COM/OData round-trips, counterparty/contract lookups) as the critical path; parsing 1000 Excel rows is negligible.
- Recommendation: measure on a client base with the 1C configurator's «Замер производительности», separately for file read, counterparty/contract resolution and document creation.
