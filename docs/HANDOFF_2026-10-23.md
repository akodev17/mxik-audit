## 2. Architecture now

```
browser ──► caddy (HTTPS tasnivo.uz) ──► /api/*  → api (NestJS, :4000)
                                      └► /*      → web (Next.js, :3000, no DB, calls api)
api, worker ──► postgres (+pgvector), redis (BullMQ)     worker: audits, doc checks, mail, telegram, cron
```

Dev without Docker for web/api: `npm run dev:api` (4000) + `npx next dev apps/web -p 3001`
(web proxies `/api/*` to `API_INTERNAL_URL`, default `http://localhost:4000`). Audits run inline in
the API unless `JOBS_MODE=bullmq` and a worker + Redis are up.

## 3. Setting up a new machine

```bash
git clone git@github.com:akodev17/mxik-audit.git && cd mxik-audit
cp .env.example .env            # fill DATABASE_URL (54329), SESSION_SECRET (32+), others as needed
docker compose up -d            # db + redis only (default profile)
npm install && npx prisma generate
npx prisma migrate deploy && npm run seed      # seed user: buxgalter@demo.uz / demo12345
npm run load:db / ingest / embed:catalog        # classifier (see DEPLOY.md §5; embedding ~3–4 h CPU)
npm run typecheck && npm run lint && npm test   # tests need the db; use DATABASE_URL=...&connection_limit=4 when several processes share it
npm run dev:api                                 # terminal 1
npx next dev apps/web -p 3001                   # terminal 2
```

Gotchas learned today:
- Always run from the repository root (packages are TypeScript source resolved via `exports`).
- `tsx watch` processes crash if `npm install` runs while they are up — restart them after installs.
- Never `rm -rf apps/web/.next` while `next dev` is running (it loses its manifests).
- Claude Code worktrees: fresh worktrees resolve `@tasnivo/*` to the main checkout's packages unless
  `node_modules` junctions are created in the worktree (`npm ci` in the worktree is the safe way).
- Shared dev Postgres has `max_connections=100`: several web/API/test processes exhaust it; append
  `&connection_limit=4` to `DATABASE_URL` per process.
- e2e: `E2E_CHANNEL=msedge` runs Playwright in installed Edge (its own Chromium is not downloaded);
  behind Caddy every browser shares one client IP, so two full runs back to back hit the sign-in
  rate limit — wait a few minutes or clear `auth_attempt` rows.
- Merging parallel session branches: conflicts cluster in `package.json`/lockfile (regenerate with
  `npm install`), `tsconfig.json`, `apps/api/src/app.module.ts` (hand-merge the module list),
  `docs/*PLAN.md` notes (keep both), `packages/i18n/src/i18n-parts/index.ts` (keep both spreads).
