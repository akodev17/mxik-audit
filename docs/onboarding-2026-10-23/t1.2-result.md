## What was done

An in-house guided tour (plan Q1: no library) on the app's own primitives: `Portal` (into `.app`, so the
dark theme applies), `useEscape` (layer stack), `useScrollLock`, `useReturnFocus`, `trapTab`, `Button`,
`useMediaQuery`. No new dependency. No persistence and no auto-start (T1.4); the only way to open it is
the temporary dev trigger `/dashboard?tour=1`.

- **Steps** (`ui/tour/tour-steps.ts`): `TOUR_STEPS`, 14 steps in the plan's order with the plan's targets
  (table below). Keys only, no copy. `visibleSteps()` filters by ability, `clampIndex()` keeps the index valid.
- **Copy placeholder** (`ui/tour/tour-copy.ts`): typed exactly like T1.3's `ta.tourX` (`_area, label,
  counter(n, total), next, back, skip, done, open, menuEntry, settingsTitle, settingsHint, settingsButton,
  steps: Record<StepKey, {title, body}>`), uz + ru from the plan's draft, marked
  `// placeholder until i18n-parts/tour.ts lands (T1.3)`. Kept in its own file rather than in
  tour-steps.ts, because the prompt also says tour-steps.ts holds keys only.
- **Engine** (`tour-context.tsx`): `TourProvider` + `useTour()`; state open / index / mode; `start()` goes
  to /dashboard first from any other route and opens once the dashboard is the current route.
- **Target resolution** (`tour-target.ts`, `use-tour-target.ts`): first visible `[data-tour=<key>]`
  (`getClientRects().length > 0`) in priority order; polls with requestAnimationFrame for up to 1 500 ms,
  else the step is a centred card (never skipped). Re-measures on resize, scroll (capture), a
  `ResizeObserver` on the target and DOM changes inside `.app`, so a tab that moves into "more" is found
  again by its next key, and a target that renders after the wait still gets its spotlight. Scrolls the
  target into view once per step (`block: 'center'`), only when it is not already fully on screen.
  Below `md` (768 px) every step is centred.
- **Overlay** (`tour-overlay.tsx`): Portal into `.app`, `z-modal`; one full-screen layer swallows every press
  (the target is visible but not clickable; pressing the backdrop does not move focus). Spotlight = one
  element over the target (6 px padding, `rounded-md`, `ring-2 ring-brand`) whose spread shadow is
  `var(--color-overlay)`; centred mode = a plain `bg-overlay` layer. Registers with the layer stack
  (`useEscape`), locks scroll, and while open `.app [aria-modal="true"]` exists, so the palette shortcut is off.
- **Card** (`tour-card.tsx`): `role="dialog"`, `aria-modal`, `aria-labelledby` title, `aria-describedby`
  body; counter `n / total` with `aria-live="polite"`; Skip (ghost, hidden on the last step), Back
  (hidden on the first), Next (Done label on the last), optional "open section" link when the step has
  `href` (the tour stays open across that navigation; it lives in the persistent frame). Placed beside the
  spotlight (bottom → top → right → left, 12 px gap, 16 px gutter, slid along the side to stay inside),
  centred when no target or no side fits. Width `min(22rem, calc(100vw - 2rem))`, max height
  `100dvh - 2rem` with scroll. Tokens only: `bg-raised`, `border-line`, `shadow-overlay`, `rounded-lg`,
  `text-h2` / `text-body` / `text-small`; animations only behind `motion-safe:`.
- **Keyboard**: Tab / Shift+Tab trapped in the card (capture-phase listener, so focus is pulled back even
  if it was elsewhere); initial focus on Next; ArrowRight / ArrowLeft = next / back (ignored with Alt,
  Ctrl, Meta or Shift, so Alt+Left stays browser-back); Escape = skip; focus returns to the opener on close.
- **Mounting**: `TourProvider` wraps the frame inside `ToastProvider` in `ui/shell/app-frame.tsx` (so the
  user menu and settings can call `useTour()` in T1.4), `<TourOverlay />` and `<TourDevTrigger />` after the
  command palette. Closed tour = no extra DOM (verified: no `.z-modal` layer in `.app`), no layout change.
- **Unit tests** (`ui/tour/tour.test.ts`, node:test, 13 tests): step order and fallbacks, ability filtering,
  index clamping, target priority resolution, spotlight padding/clamping, card placement for header tabs,
  right-edge buttons, tall targets, no-room cases and a phone.

## For T1.4: the API to wire blind

```ts
import { TourProvider, useTour, type TourDoneReason } from '@/ui/tour/tour-context';

<TourProvider canWrite={canUpload} canManageTeam={shell.canManageTeam} onDone={(reason) => …}>
// already mounted in app-frame.tsx without onDone; add it there.
// onDone(reason: 'finished' | 'skipped') fires once per close:
//   'finished' = Next on the last step; 'skipped' = Skip or Escape.

const tour = useTour();
tour.open      // boolean
tour.index     // number, index into tour.steps
tour.step      // TourStep | null  ({ key, targets, href?, requires? })
tour.steps     // TourStep[] visible to this user (upload only with canWrite)
tour.mode      // 'spotlight' | 'centred' (current step found its target or not)
tour.start()   // opens on step 1; from another route pushes /dashboard first, opens when it is current
tour.next()    // last step: same as finish()
tour.back()
tour.skip()    // closes, onDone('skipped')
tour.finish()  // closes, onDone('finished')
```

- Re-open from the user menu / Settings: call `tour.start()`. Opener focus is restored on close
  (verified with the search button as opener).
- Remove `ui/tour/tour-dev-trigger.tsx` and its two lines in app-frame.tsx (import + `<Suspense>`).

## Deviations from the plan, and why

- **`roles?: Role[]` became `requires?: ('write' | 'team')[]`.** The frame's data (`ShellData`) carries no
  role, only `canWrite` / `canManageTeam`, and the prompt's own example ("upload only when `shell.canWrite`")
  is a capability. The provider gets `canWrite = shell.canWrite && !shell.demo` (the rail's upload condition).
- **API port variable is `API_PORT`**, not `PORT` (`apps/api/src/config/env.ts`).
- **At 1024 px the bank tab is not in "more"** (the plan expected bank/didox/products/onec there). With the
  sidebar icons-only at 1024, the row fits up to "Bank koʻchirmalari"; products, didox, onec, dictionary and
  activity spotlight "more". Behaviour follows the DOM, so a narrower window or a wider sidebar moves more
  tabs into "more" without changes.
- **Spotlight drawing**: one rounded element with a spread `box-shadow` of `var(--color-overlay)` instead of an
  SVG mask (the prompt allowed "an SVG mask or four rects"). Same token in both themes, one element.
- **scrollIntoView only when the target is not fully visible**, to avoid jumping the page for header targets.
- `ui/dialog.tsx`, `placement.ts`, `layers.ts`, `overlay.ts`, `focus.ts` are unchanged; placement for an
  arbitrary rect is a 40-line `tour-place.ts` (the existing `placePanel` only does top/bottom of a trigger).
