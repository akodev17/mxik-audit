# T1.3 result: tour copy (uz + ru) in the i18n package

Branch `feat/tour-copy` (cut from `main` at `2908238`), not pushed, not merged.

## Files changed

- `packages/i18n/src/i18n-parts/tour.ts` (new): `uz` and `ru` with
  `{ tourX: { _area: 'tour', label, counter(n, total), next, back, skip, done, open, menuEntry,
  settingsTitle, settingsHint, settingsButton, steps } }`. `steps` has the 14 fixed keys in plan
  order. Also exports `TOUR_STEP_KEYS` (the same 14 keys, in order) and `type TourStepKey`, so
  T1.2 can type its step list against the copy if it wants. `uz.tourX.steps` is checked with
  `satisfies Record<TourStepKey, …>`, and `ru: typeof uz` means a missing ru step does not compile.
- `packages/i18n/src/i18n-parts/index.ts`: `tour` imported and spread into `partsUz` and `partsRu`.
- `packages/i18n/src/i18n-parts/tour.test.ts` (new), 6 tests:
  - ru and uz have the same keys in the same order;
  - the steps are exactly `TOUR_STEP_KEYS`, in order;
  - no `'`, `` ` ``, `‘`, `’` in any string (Uzbek uses U+02BB / U+02BC only);
  - every body is ≤ 160 characters and ≤ 2 sentences and contains none of
    integratsiya / sinxronizatsiya / parser / OData / API (or their Russian forms);
  - every section title equals the label the app shows for it (`nav.*`, `shellX.nav.*`,
    `accountingX.nav.*` read through `appDict`), so a later rename of a nav label fails this test;
  - `counter(3, 14)` is `3 / 14` in both languages.

No existing string changed. No web-app file touched.
