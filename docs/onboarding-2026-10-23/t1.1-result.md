## For T1.4: what to call

| What | Name |
|---|---|
| Endpoint key | **`account.setTour`**: `PUT /api/account/tour`, body `{ done: boolean }`, answers `{ ok: true }` |
| Web call | `api.account.setTour({ done: true })` (`apps/web/src/lib/api/browser.ts`; the client is derived from the contracts, nothing hand-written) |
| Shell field | **`tour: 'pending' \| 'done'`** on `notifications.shell` (`GET /api/shell`), so `ShellData['tour']` in `apps/web/src/ui/shell/shell-queries.ts` |
| Who | `auth: 'session'`, `role: 'any'` (admins, accountants and viewers), CSRF header required like every PUT, no `noDemo` |

- `done: true` sets `User.tourCompletedAt = now()`; call it on both `finished` and `skipped`.
- `done: false` clears it, so the tour opens again on the next visit. **For tests and support only**:
  "show the tour again" in the menu should open the tour without calling it.
- Demo: the PUT answers `{ ok: true }` and writes nothing; the shell always answers `tour: 'done'`.
  A demo counts if the session says demo or the org's `kind` is `demo` in the database.
- If the flag can't be read, the shell answers `tour: 'done'`, the same way `unread` falls back to
  null. A database hiccup never forces the modal tour onto every page.
- I used the shell payload, not `auth.me`, because the signed-in frame's data comes from
  `notifications.shell()` (`apps/web/src/app/(app)/layout.tsx:11` passes it to the frame).
  `CurrentUser` is unchanged.

## Where the code differs from the plan

- The shell payload is built in `packages/domain/src/shell-frame.ts`, not in `apps/api/src/notifications/*`.
  The controller only calls `shellFrame(user)`, so the field was added in the domain.
- The shell route is `GET /api/shell`, not `/api/notifications/shell`.
- The API port is set by `API_PORT`, not `PORT` (`apps/api/src/config/env.ts:13`). `PORT=40xx npm run dev:api`
  still binds 4000. Use `API_PORT=4031 npm run dev:api`.
- New endpoints must name a `replaces` entry (`checklist.test.ts`). `setTour` uses
  `page:(app)/layout#shell`, which is allowed to repeat.
- "What breaks" in the rollback guide: the plan's wording ("the tour opens on every visit") doesn't
  match the code. With the column gone, the shell falls back to `done`, so the tour never opens on
  its own and the PUT answers 500. The guide says that.
