## What was done

- **Copy swap.** `ui/tour/tour-copy.ts` is deleted. The card reads `useI18n().ta.tourX` directly
  (`useTourCopy()` had only that one caller, so it went with the file). `STEP_KEYS` / `StepKey` in
  `tour-steps.ts` are now T1.3's `TOUR_STEP_KEYS` / `TourStepKey`, so a step without copy fails typecheck.
- **Accessible name** (owner decision): the dialog is `aria-label={ta.tourX.label}`. The visible step
  title and the body make up its description (`aria-describedby="<title> <body>"`). The counter stays
  `aria-live="polite"`.
- **"Open section" link**: unchanged, the tour stays open over the new page (owner decision).
- **Auto-start** (`ui/tour/tour-auto-start.tsx`): it calls `start()` once per page load (a ref), only on
  `/dashboard`, when `shell.tour === 'pending'` and the session isn't a demo. It waits 600 ms after the
  dashboard mounts. While another `.app [aria-modal="true"]` is open, it re-checks every 600 ms and
  opens when that dialog closes.
- **Saved flag** (`ui/tour/use-tour-flag.ts`, `ui/tour/tour-save.ts`): `onDone` (finished or skipped)
  calls `api.account.setTour({ done: true })`. If that fails, it retries once after 2 s, then gives up
  silently. Local state flips to "done" at once, so neither a client navigation nor a refreshed shell
  that still says pending reopens it in this session. A tour re-opened from the menu or Settings
  closes without a write.
- **Re-open entries**:
  - User menu: a new item "Platformani oʻrganish" (`ta.tourX.menuEntry`, `IconSparkle`) directly
    under Help. It closes the menu with focus on the avatar, then calls `start()`.
  - Settings → Account: a card with `settingsTitle`, `settingsHint` and a secondary Button
    `settingsButton` (`settings/tour-setting.tsx`). It calls `start()`, which goes to /dashboard first.
  - Both are hidden in a demo (see open questions).
- **Dev trigger removed**: `tour-dev-trigger.tsx` and its two lines in `app-frame.tsx` are gone.
- **Mobile**: the card is a column, and only the words scroll on a short screen. The Skip, Back and
  Next row never scrolls away. Below `md` the buttons are `h-control-lg` (40 px). `max-h` uses `dvh`
  (T1.2). Body text is `text-body` (14 px).
- **Focus-return fix** (found during the checks, `bd131fe`): the card's `useReturnFocus` recorded
  its own Next button as the opener on React StrictMode's dev double mount. Closing a tour re-opened
  from the user menu left focus on `<body>`. `TourProvider` now keeps `document.activeElement` when
  `start()` is called and gives focus back after the card is gone. If the opener left the page (a
  start from another route), focus is not moved.
- **Fixtures**:
  - `apps/web/e2e/fixture.ts`: `setupFirm` and `setupEmptyOrg` create users with `tourCompletedAt`
    already set, so the existing e2e suite isn't covered by the overlay. The file also exports
    `TA_RU = appDict('ru')` for the new test.
  - `packages/db/prisma/seed.ts`: the seed user is created with `tourCompletedAt`.
  - `scripts/seed-demo.ts` creates no users.
  - Demo users (`packages/domain/src/demo.ts`) are left alone: the shell answers `done` for every
    demo (T1.1), and the frame also checks `!shell.demo`.
- **New e2e** `apps/web/e2e/onboarding-tour.e2e.ts`, two tests (about 12 s together):
  - A user with `tourCompletedAt = null` signs in. The dialog named "Platforma bilan tanishuv" is on
    `/dashboard`. Opening it writes nothing. Next twice (counter 3 / 14), then Skip. The flag is saved
    in the DB, and a reload shows no tour. The user-menu entry re-opens it on 1 / 14. Escape returns
    focus to the account button.
  - ru: the Settings → Account button opens the tour on `/dashboard`. Every one of the 14 cards shows
    the `ru` title, body and counter, and the last button ("Начать") closes it.
- **Unit tests** (`ui/tour/tour.test.ts`, now 15): two new tests cover the save. One write goes
  through on the first try; a failed write is retried once after `RETRY_MS`, and two failures give up.
