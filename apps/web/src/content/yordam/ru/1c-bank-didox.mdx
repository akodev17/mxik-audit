Tasnivo избавляет от ручного ввода в 1С банковской выписки, счёта-фактуры Didox и списка товаров: вы загружаете файл, программа читает и проверяет строки, вы просматриваете сомнительные места и подтверждаете, а на выходе получаете файл для загрузки в 1С.

## Общий путь

Все три раздела проходят один путь: источник → чтение → сопоставление → проверка → подтверждение → файл для 1С.

Каждый загруженный файл называется **пакетом**. Статусы пакета: Загружено, Прочитано, На проверке, Подтверждено, Подготовлено для 1С, Ошибка. У каждой записи внутри пакета свой статус: Корректно, Исправлено, Сомнительно, Не решено, Пропущено, Передано в 1С.

Программа никогда не решает сама: запись, которую правила не смогли разобрать, остаётся **Не решено**, а подсказка искусственного интеллекта остаётся только подсказкой, пока вы её не примете.

## Банковские выписки

1. На странице **Банковские выписки** загрузите выписку Excel или CSV, скачанную из банка (выберите, для какого клиента).
2. Программа сама распознаёт столбцы. Если не распознала, вы один раз указываете их вручную; для следующей выписки этого банка разметка запоминается.
3. Строки читаются: дата, сумма, контрагент (ИНН, счёт, МФО), назначение платежа. Начальный и конечный остаток сверяются с выпиской. Повторный платёж отмечается.
4. Вид операции определяется правилами (например, услуги банка, оплата от клиента). Свои правила добавляются в настройках на странице **Банковские выписки**.
5. Вы просматриваете сомнительные и нерешённые строки и подтверждаете пакет.
6. Из подтверждённого пакета формируются файл `kl_to_1c.txt` и отчёт сверки.

## Счета-фактуры Didox

1. На странице **Счета-фактуры Didox** загрузите архив, скачанный из Didox (.zip), один документ JSON или шаблон ЭСФ Excel (.xlsx, до 20 МБ).
2. Другой путь: администратор вводит токен Didox в разделе Настройки → **Подключение Didox**, после чего новые счета-фактуры забираются напрямую. Этот путь ещё не проверен с настоящим Didox (см. ниже).
3. Строки счёта-фактуры сопоставляются с вашим каталогом товаров: проверяются код ИКПУ, код упаковки и единица измерения. Товар, которого нет в каталоге, получает статус **Не решено**.
4. Вы просматриваете строки и подтверждаете счёт-фактуру.
5. Результат: файл Excel с поступлением товаров (по листу на каждый счёт-фактуру) и файл Excel с номенклатурой.

## Каталог товаров

**Каталог товаров** — единый список товаров вашей фирмы и клиентов. Товары попадают в него тремя путями: из файла Excel, из выгрузки 1С «Номенклатура» или кнопкой **Добавить в каталог товаров** на странице завершённой проверки.

Для каждого товара проверяется: есть ли код ИКПУ в классификаторе, действует ли он ещё, не ограничен ли он, соответствуют ли коду код упаковки и единица измерения. При несоответствии появляется предложение; решение принимаете вы кнопкой **Подтвердить ИКПУ**. Подтверждённый код записывается и в словарь фирмы: [Словарь фирмы](/yordam/ru/firma-lugati).

Подтверждённый список скачивается как файл Excel с номенклатурой для 1С.

## Загрузка в 1С

На странице **Импорт в 1С и история** все пакеты в одном списке: банк, Didox и товары. Откройте пакет и нажмите **Подготовить для 1С**: программа покажет, что попадёт в файл, что будет пропущено и какие есть предупреждения; пока ничего не меняется. Затем файл скачивается.

Виды файлов и куда они загружаются в 1С:

- `kl_to_1c.txt` — банковская выписка: Банк и касса → Банковские выписки → Загрузить.
- `postuplenie-…xlsx` — счёт-фактура Didox: Поступление товаров и услуг, загрузка из таблицы.
- `…-nomenklatura.xlsx` — список товаров: Номенклатура → Загрузить из файла.
- `…-kontragenty.xlsx` — новые контрагенты: Контрагенты, загрузка из таблицы.

Если запись, уже переданная в 1С, приходит снова, программа это отмечает, поэтому платёж или счёт-фактура не попадут в 1С дважды. Список контрагентов можно выгрузить из 1С и загрузить сюда: тогда строки выписки проще привязываются к знакомым контрагентам.

В разделе **Настройки 1С** выбирается вид подключения: только файлы (основной путь), прямое подключение (OData) или HTTP-сервис. Здесь же вариант ключа МФО для банковского файла: стандартный или с дополнительным ключом для узбекской редакции.

## Что значит «Не решено»

**Не решено** — запись, которую программа не смогла уверенно разобрать: контрагент не найден, товара нет в каталоге, кода ИКПУ нет в классификаторе или правила не определили вид операции. Такая запись в файл не попадает. Вы либо исправляете её, либо оставляете без файла кнопкой **Пропустить**; оба решения остаются в истории.

## Статус проверки

Текущее состояние названо открыто, потому что ошибка в бухгалтерских документах стоит дорого:

- Файлы составлены по стандарту обмена 1С, но ещё не загружались в настоящую базу «1С:Бухгалтерия (для Узбекистана)». Проверьте первый файл в тестовой базе.
- Чтение банковских выписок проверено на синтетических примерах; с настоящим файлом банка ещё не подтверждено.
- Структура документов Didox взята из сторонних источников; прямое подключение не проверено с настоящим Didox. Загрузка архива работает.
- Прямое подключение к 1С (OData) не проверено на настоящей базе; основной путь — загрузка через файл.
